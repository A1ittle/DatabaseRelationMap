# 锁定规则（开发时不要改语义）

对照文件：`prototype/lineage-map-v2.html` 中的 `liveEdges()`、`buildTree()`、`shortestDown()`。

这些规则已经在原型里验证过。接口字段名可以按你们的规范改，**判定结果必须与原型一致**。用 `fixtures/seed-ods-trade-order.expected.json` 和 `node spec/verify-tree.mjs` 做回归。

---

## 1. 只画下游

从当前表（seed，必须是 `type === 'table'`）只向下游 BFS。

- 入边、上游表、侧输入（如 `dim.merchant`）**不进这棵树**
- 搜索可以命中「不在当前下游」的表，选中后是 **换根**，不是把上游画进来
- 若以后要看「这张下游视图还读了哪些外部维表」，单独做「侧输入」抽屉，不要混进主干

## 2. Java 是叶子

`liveEdges` 丢掉所有 `from.type === 'java'` 的边。

即使采集到 Java 写出表或调用其他程序，**本产品第一期也不画**。Java 卡片文案：不写出表，也不调用其他程序。

## 3. 一节点一条主父边

可达子图里，每个非根节点只保留一条进入它的 **主依赖**（实线）。

其余仍在可达子图内的边标成 **跨支**（虚线）。跨支不是错误，是两条下游链之间的汇合 / 旁路。

自环（`from === to`）丢弃。

## 4. 主父边怎么选

对每个节点，在所有「从 seed 能走到它」的入边里选一条：

1. **更长路径优先**（hop / rank 更大）
2. 路径长度并列时，关系强度：`writes(3) > derives(2) > calls(1) > reads(0)`
3. 仍并列：保持先写入的那条（稳定，不随机）

根节点 rank = 0，没有父边。

环或 Kahn 漏掉的节点：非根记 rank = 1，没有主父边，其入边全部当跨支。

## 5. 视图分工（不要把四种视图做成同一张图的滤镜）

| mode | 产品名 | 干什么 |
|---|---|---|
| `focus` | 下游树 | 按 hop 分列画节点；默认 1 层；`+N` 展开树子节点 |
| `overview` | 分层总览 | 按 hop × 类型聚类；「全部」必须走这视图，禁止一次铺开全部叶子 |
| `impact` | 影响清单 | 清点下游对象 + 单独一列跨支关联 |
| `path` | 调用路径 | seed → 某一下游（优先 Java 终端）的最短下游路径；路径上的跨支要标出来 |

## 6. 交互契约（已验证，按同样行为实现）

1. 点节点 → 选中 + 高亮主路径 + 打开详情
2. 点 `+N` / 「展开子节点」→ 只展开该节点的 **树** 子节点（不是跨支邻居）
3. 双击表 / 「把这张表设为根」→ 以该表重算下游树
4. 关掉全部类型 → 空状态 + 「显示全部类型」
5. 搜索无结果 → 明确说没匹配到什么
6. Esc：先关搜索，再回到当前表

## 7. 明确不做（第一期）

- 字段级血缘
- 上游 / 双向全景
- Java 出边
- 一次渲染 500+ 叶子节点
- 把跨支画成和第二条主父边同权的实线
