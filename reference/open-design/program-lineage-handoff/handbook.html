这份包是什么

HTML 原型是验收标准，不是可上线源码。后端按本手册返回已经拆好的主依赖 / 跨支；前端按四种视图画出来。

角色先看
产品 / QA锁定规则 → 交互验收 → 打开原型
后端领域模型 → 接口 → 拆树算法 + node spec/verify-tree.mjs
前端四视图状态机 → 交互 → spec/types.ts 与 tokens

锁定规则

  1. 只画下游。从当前表 BFS。上游和侧输入（如 dim.merchant）不进树。搜索到域外表是换根，不是把上游画进来。
  2. Java 是叶子。from.type === 'java' 的边全部丢掉。Java 不写出表，也不调用其他程序。
  3. 一节点一条主父边。其余仍在可达子图内的边是跨支，画虚线。自环丢弃。
  4. 主父边判定：更长路径优先；并列时 writes > derives > calls > reads。
第一期明确不做 字段级血缘、上游/双向全景、Java 出边、一次铺开 500+ 叶子、把跨支画成第二条等权实线。

领域模型

type Node = {
  id: string
  name: string          // 技术名，等宽
  title: string         // 中文名
  type: 'table' | 'view' | 'procedure' | 'java'
  owner: string
  system: string
  status: 'verified' | 'inferred'
  desc?: string
}

type Edge = {
  from: string
  to: string
  rel: 'reads' | 'writes' | 'calls' | 'derives'
}

只有 table 能当 seed。id 可含点号，选择器用 data-id，不要当 CSS class。

表 视图 存储过程 Java 终端

接口

完整 schema 见 spec/openapi.yaml。原则：树的拆分后端做，前端只画。

方法路径用途
GET/lineage?seed=&depth=&expand=下游树。返回 nodes / tree / cross / rank / parent / stats
GET/lineage/children?seed=&id=懒展开 tree 子节点
GET/lineage/search?q=&seed=搜索。表可不在当前下游（用于换根）
GET/lineage/nodes/{id}?seed=详情邻接
GET/lineage/path?from=&to=最短下游路径，边上标 tree | cross

错误码：INVALID_SEED 400 · FORBIDDEN 403 · SEED_NOT_FOUND 404 · LINEAGE_NOT_COLLECTED 409。

URL 状态：?seed=&sel=&mode=&depth=&types=，不要只靠 localStorage。

stats 按整棵可达下游计（权限过滤后），不要按当前可见节点计。默认 depth=1；all 走总览聚类。

四视图状态机

mode产品名干什么
focus下游树按 hop 分列。默认 1 层。+N 只展开 tree 子节点
overview分层总览hop × 类型聚类。「全部」必须进这里

点「全部 · 聚类」且图很大时，强制 mode = overview。禁止在下游树一次铺开全部叶子。

换根：seed = sel = tableId，清空 expanded，重拉 /lineage。Esc 先关搜索，再 sel = seed。键盘 1–4 切视图。

交互验收（16 对象）

  1. 第一列只有当前表，绿色「当前」，外面没有额外白框。
  2. 看不到 dim.merchant、core.t_order、OrderIngestJob。
  3. GmvReportService 主父是 ads.merchant_gmv（实线）；补全视图到它是虚线。
  4. v_risk_daily 主父是 dwd.fact_order；来自 seed 和风险分的是虚线。
  5. 点 +N 只多出该节点的树子节点。双击表设为根后上游消失。
