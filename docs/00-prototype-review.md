主父边优先级 `writes > derives > calls > reads` 是原型布局规则，不能解读成业务重要性、风险等级或血缘证据可信度。

## 4. 原接口文档需补齐

原 OpenAPI 的 search、nodes、path 200 响应缺 `description`；3.1 文档里使用 `nullable: true` 也不能正确表达 JSON Schema 的 null 类型。正式契约需补完整错误响应、鉴权、节点扩展字段必填性及 null 定义，并用标准验证器校验。此处为源码对照规范的静态结论，没有声称已运行 OpenAPI 验证器。[OpenAPI 3.1 规范](https://spec.openapis.org/oas/v3.1.0#response-object)

另外缺少独立影响清单、聚类分页、跨支查询和数据版本；单一 `truncated` 混合了“更深未展开”和“计算不完整”；分享 URL 不带快照，无法保证历史复现。新接口草案见第 04 文档。

## 5. 本轮没有验证的内容

没有逐项执行所有视图/键盘/触屏/空态交互；没有验证真实血缘正确率；没有性能压测；没有安装或实测候选图引擎；没有执行采集、生产权限和部署。原型仍可能有本文未列出的其他问题。

Open Design 窗口在本轮存在用户操作，最终版本以保留副本哈希为准。若源文件在此后发生变化，重新做差异核对，不覆盖本轮证据。
